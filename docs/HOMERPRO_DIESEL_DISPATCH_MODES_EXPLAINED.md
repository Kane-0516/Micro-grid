# HOMER Pro 柴油机调度模式说明

## 1. 目的

本文用于解释当前项目中用于逼近 HOMER Pro 的三种柴油机调度口径：

- `LP`
- `Proxy`
- `UC`

同时说明它们与 HOMER Pro 的关系、差异来源、典型算例，以及如何解读结果页中的对比数据。

## 2. 三种模式分别是什么意思

### 2.1 LP

`LP` 是 `Linear Programming`，即连续线性调度。

其特点是：

- 柴油机只决定“这一小时发多少电”
- 不显式决定“开机还是停机”
- 不显式建模机组启停状态
- 不强制体现真实柴油机的最小稳定负载

可以把它理解成：

- 只优化“出力多少”
- 不优化“开还是关”

优点：

- 速度最快
- 最容易求解

缺点：

- 最不像真实柴油机
- 容易出现很多低功率碎片化运行
- 往往低估真实油耗
- 往往高估运行小时的可调性

一句话：

`LP` 更像“数学上最平滑的电源”，而不是一台真实柴油发电机。

### 2.2 Proxy

`Proxy` 是当前项目默认模式。

它的基本逻辑是：

1. 先用 `LP` 求全年逐小时出力
2. 再根据柴油出力序列反推“哪些小时应该算开机”
3. 再用最小负载率、启停状态代理、最低稳定运行功率，对油耗和运行小时做修正

可以把它理解成：

- 先算出力
- 再补上真实机组约束的主要影响

它并不是完整的机组启停优化，但比纯 `LP` 更接近真实柴油机，也更接近 HOMER Pro 的结果风格。

优点：

- 速度快
- 比纯 `LP` 更接近真实机组
- 更适合作为默认在线交互模式

缺点：

- 启停状态不是在优化阶段原生决定的，而是后处理近似得到的
- 仍然不是完整 `UC`

一句话：

`Proxy` 是“速度和真实性的折中方案”。

### 2.3 UC

`UC` 是 `Unit Commitment`，中文通常叫“机组组合”或“机组启停优化”。

它与 `LP` 的本质区别是：

- 不只是算柴油机这一小时发多少电
- 还要同时决定这一小时机组“开还是关”

典型会考虑：

- 最小负载率
- 启停状态
- 最小开机时间
- 最小停机时间
- 启动成本
- 停机成本

可以把它理解成：

- `LP`：只优化“出多少”
- `UC`：优化“开不开 + 出多少”

优点：

- 最接近真实柴油机运行逻辑
- 最适合解释启停次数、低负载油耗和机组行为

缺点：

- 在 `PyPSA + 全年 8760 小时 + 储能 + 二进制变量` 的链路里最慢
- 不适合作为默认在线交互模式

一句话：

`UC` 更接近真实工程机组，但计算代价最大。

## 3. 为什么同一套输入，三种模式结果会不一样

因为真实柴油机并不是“想发多少就能连续稳定发多少”。

真实机组通常有两个关键事实：

- 一旦开机，就存在基础油耗
- 在低负载运行时，效率会明显变差

所以这三种模式的差异并不只是数学形式不同，而是对“柴油机是不是一台真实机组”的假设不同。

一般规律如下：

- `LP` 往往低估真实油耗
- `LP` 容易把柴油机切成很多小功率碎片运行
- `Proxy` 会把这类低负载小时修正得更真实
- `UC` 会直接改变最优调度路径，因为它从一开始就不允许不真实的开机状态

## 4. 直观例子一：单小时低负载

假设：

- 柴油机额定功率：`40 kW`
- 最小负载率：`30%`
- 因此最小稳定出力：`12 kW`
- 某一小时负荷：`8 kW`

### 4.1 LP 会怎么处理

`LP` 可能直接让柴油机发：

- `8 kW`

因为对它来说，只要供需平衡即可。

这时的问题是：

- 数学上成立
- 工程上不真实

因为真实机组通常不能长期稳定运行在 `8/40 = 20%` 这样低于最小负载率的状态。

### 4.2 Proxy 会怎么处理

`Proxy` 先接受 `LP` 给出的 `8 kW` 出力结果，但在油耗计算阶段会认为：

- 这一小时已经算“机组开机”
- 既然机组开机，就不应按 `8 kW` 的理想化状态算油耗
- 而应至少按最小负载 `12 kW` 对应的运行状态修正油耗

因此：

- 供电结果仍然可能保留 `8 kW`
- 但油耗会按更真实的开机状态进行修正

### 4.3 UC 会怎么处理

`UC` 在优化阶段就知道：

- 这台机组开机后不能低于 `12 kW`

所以它不会允许“开机却只发 `8 kW`”这种状态进入最优解。

它只能在这些策略中选择：

- 不开机，让电池供电
- 开机并至少发 `12 kW`
- 多出的电去充电或被弃掉
- 在更长时间尺度上调整启停时点，减少总成本

这就是为什么 `UC` 在行为上最接近真实机组。

## 5. 直观例子二：连续 6 小时负荷变化

仍然假设：

- 柴油机额定功率：`40 kW`
- 最小负载率：`30%`
- 最小稳定出力：`12 kW`

负荷序列如下：

- 第1小时：`5 kW`
- 第2小时：`8 kW`
- 第3小时：`15 kW`
- 第4小时：`6 kW`
- 第5小时：`18 kW`
- 第6小时：`4 kW`

并假设：

- 电池容量有限，但不是无限大
- 柴油机每次启动都有代价
- 频繁低负载运行不划算

### 5.1 LP 的典型思路

`LP` 只关心每小时平衡，不关心真实启停。

它可能会给出一条几乎“紧贴负荷”的柴油出力：

- 第1小时：`5`
- 第2小时：`8`
- 第3小时：`15`
- 第4小时：`6`
- 第5小时：`18`
- 第6小时：`4`

这条曲线在数学上很好看，但工程上不真实：

- 柴油机像一个无限可调电源
- 完全没有最小稳定出力的约束

### 5.2 Proxy 的典型思路

`Proxy` 仍然从 `LP` 出力开始，但后处理会做两件事：

- 识别哪些小时应该算作“机组开机”
- 在这些开机小时里，用最小负载约束修正油耗

所以它可能会认为：

- 某几个连续小时应视为同一段开机区间
- 低于最小负载的小时虽然仍保留原始供电结果，但燃油不再按理想值计算

其结果通常表现为：

- 油耗比 `LP` 更高
- 运行小时更合理
- 可以统计出更合理的启动次数

### 5.3 UC 的典型思路

`UC` 的优化目标不是“每小时尽量刚好跟着负荷”，而是“考虑真实机组代价后的全年总最优”。

因此它可能做出这种策略：

- 第1小时：先不开机，电池顶负荷
- 第2小时：继续不开机，避免提前启动
- 第3小时：开机，满足较高负荷
- 第4小时：即使负荷只有 `6 kW`，也可能继续开机，以避免停机后又启动
- 第5小时：继续开机，满足 `18 kW`
- 第6小时：如果后续负荷低，则停机，由电池承担

这意味着在 `UC` 下：

- 有些低负荷小时，柴油机根本不开
- 有些小时虽然负荷很低，但机组仍维持最小稳定出力
- 多余的电可能用于充电或弃电
- 机组行为更像现实而不是像一个理想可调电源

## 6. 为什么 HOMER Pro 看起来很快，而 UC 在当前项目里很慢

这并不意味着两者在求解完全相同的问题。

当前项目的 `UC` 慢，主要因为：

- 采用的是 `PyPSA + 通用优化器`
- 做的是全年 `8760` 小时带二进制启停变量的优化
- 还叠加了储能 SOC、充放电、弃光、缺供等耦合变量

这类问题一旦上全年 `UC`，求解规模会显著膨胀。

HOMER Pro 更可能采用的是：

- 专用微电网 dispatch 仿真逻辑
- 针对 PV/储能/柴油机的专门求解流程
- 更强的方案筛选与剪枝
- 专用工程优化实现

因此：

- 看起来都在做“全年 + 启停 + 经济对比”
- 但底层求解路线很可能并不一样

这也是为什么当前项目默认采用 `Proxy` 作为在线模式：

- 比 `LP` 更接近真实和 HOMER Pro
- 比 `UC` 快得多
- 更适合页面交互和日常测试

## 7. 当前项目与 HOMER Pro 的关系

当前实现并不是“与 HOMER Pro 一模一样”。

更准确地说：

- 经济主口径已经明显朝 HOMER Pro 对齐
- 燃油曲线也已采用 HOMER 风格线性模型
- 纯柴油基准场景已经改为独立仿真
- 默认柴油调度采用 `Proxy`，用来在精度和速度之间逼近 HOMER Pro

但仍然不是完全一致，主要原因包括：

- 调度引擎不完全相同
- 电池 dispatch 规则未完全复刻 HOMER Pro
- 输入时序数据不一定和 HOMER Pro 完全一致
- 柴油机参数、维护参数、寿命参数可能未完全按同一设备卡校准

因此当前阶段的正确表述应为：

- 不是“完全等同 HOMER Pro”
- 而是“尽量复现 HOMER Pro 的主要建模口径与结果趋势”

## 8. 三模式结果页应该怎么解读

在结果页中，对同一组项目输入分别运行 `LP / Proxy / UC` 时，最值得重点观察的指标包括：

- `mgDieselLiters`
- `mgDieselHours`
- `mgDieselStarts`
- `microgridNpcUsd`
- `finalMgLcoe`

建议的解读方式如下。

### 8.1 如果 LP 的柴油升数明显最低

这通常说明：

- 连续可调的理想化假设使柴油机过于“省油”
- 低负载小时没有充分体现真实油耗惩罚

### 8.2 如果 Proxy 比 LP 油耗高，但仍明显快于 UC

这通常说明：

- 最小负载率和启停状态代理确实在发挥作用
- `Proxy` 正在把结果往真实机组方向拉近
- 这是目前最适合默认模式的状态

### 8.3 如果 UC 的启动次数和运行小时与 Proxy 接近

这说明：

- `Proxy` 作为近似手段已经比较成功
- 后续不一定需要把全年 `UC` 作为默认模式

### 8.4 如果 UC 和 Proxy 差异仍然很大

这说明：

- 机组启停逻辑对当前项目影响很大
- 需要进一步校准：
  - 最小负载率
  - 最小开停机时间
  - 启停成本
  - 电池与柴发的协调策略

## 9. 对客户或内部汇报时的解释模板

可直接使用以下表述。

### 9.1 简短版

本系统提供三种柴油机调度口径：

- `LP`：连续调度，速度最快，但偏理想化
- `Proxy`：在 LP 结果上补偿启停和最小负载影响，是默认模式
- `UC`：完整机组启停优化，最接近真实柴油机，但计算最慢

默认使用 `Proxy`，因为它在计算速度和对 HOMER Pro 的逼近程度之间更平衡。

### 9.2 技术版

`LP` 将柴油机视为连续可调电源，只优化逐小时出力；`UC` 同时优化开机状态与出力，并体现最小负载、启停代价与运行约束；`Proxy` 则先求得 `LP` 出力，再通过启停状态代理与最小负载燃油修正，补偿理想化连续机组带来的偏差。

因此在同一项目下，`LP / Proxy / UC` 会分别对应不同的年油耗、运行小时、启动次数、NPC 和 COE。当前项目默认使用 `Proxy` 作为在线分析模式，以在求解速度可接受的前提下尽量逼近 HOMER Pro 的结果风格。

## 10. 推荐使用建议

当前阶段建议如下：

- 页面默认分析：使用 `Proxy`
- 快速敏感性分析：比较 `LP` 和 `Proxy`
- 深度校准和对标：再额外测试 `UC`
- 若目标是进一步逼近 HOMER Pro：
  - 先统一 `8760` 负荷与资源数据
  - 再校准柴油机参数
  - 最后再继续推进更接近 HOMER 的专用 dispatch 规则

## 11. 一句话结论

三种模式的本质区别在于：

- `LP` 把柴油机当理想电源
- `Proxy` 承认它是现实机组，但用后处理近似修正
- `UC` 从优化阶段起就把它当成真实机组

因此如果目标是“速度 + 接近 HOMER Pro”，当前默认采用 `Proxy` 是合理的；如果目标是“最真实的启停逻辑”，则应使用 `UC` 做验证。

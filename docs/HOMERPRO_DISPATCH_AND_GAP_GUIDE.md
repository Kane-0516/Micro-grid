# HOMER Pro 调度模式与偏差说明总文档

## 1. 目的

本文用于统一说明当前项目中与 HOMER Pro 对标时最关键的两部分内容：

- 柴油机调度模式 `LP / Proxy / UC` 的含义
- 为什么当前结果仍会与 HOMER Pro 存在偏差，尤其是柴油机运行时间、油耗、NPC、COE 等指标

本文适合作为：

- 内部技术说明
- 结果页偏差解释依据
- 后续继续逼近 HOMER Pro 的开发路线说明

## 2. 当前是不是和 HOMER Pro 一模一样

不是一模一样，当前实现是“尽量对齐 HOMER Pro 口径”，但还没有做到“同输入下逐项完全一致”。

### 2.1 已经明显对齐的部分

当前已经对齐得比较多的部分包括：

- 成本/经济主口径已经切到 `NPC -> annualized cost -> COE`
- 柴油燃油已经改成 HOMER 风格线性燃油曲线
- 纯柴油基准场景已经改成独立仿真，不再是经验换算
- 柴油机寿命、电池寿命、残值、贴现现金流这些已经按 HOMER 思路重构了
- 后端已经支持三种柴油调度模式，默认是 `proxy`

### 2.2 仍然没有完全一致的关键点

当前与 HOMER Pro 仍不完全一样的关键点包括：

- 电池控制逻辑不一样
  HOMER 常见的 `Load Following / Cycle Charging / reserve SOC / generator charging` 规则，我们这边还没完整复刻。
- 输入数据源可能不一样
  如果没有导入和 HOMER 完全相同的 `8760` 负荷、气象、温度序列，结果不会完全一致。
- 柴油机细节参数还没完全按 HOMER 设备卡校准
  比如最小负载、燃油曲线系数、启动成本、寿命小时数、维护参数，差一点都会把年油耗和年运行时间拉开。

所以更准确的说法是：

- 当前实现已经明显更接近 HOMER Pro
- 但还不是“与 HOMER Pro 一模一样”

## 3. 三种柴油机调度模式分别是什么意思

### 3.1 LP

`LP` 是 `Linear Programming`，即连续线性调度。

其特点是：

- 柴油机只决定“这一小时发多少电”
- 不显式决定“开机还是停机”
- 不显式建模机组启停状态
- 不强制体现真实柴油机的最小稳定负载

可以把它理解成：

- 只优化“出力多少”
- 不优化“开还是关”

优点：

- 速度最快
- 最容易求解

缺点：

- 最不像真实柴油机
- 容易出现很多低功率碎片化运行
- 往往低估真实油耗
- 往往高估运行小时的可调性

一句话：

`LP` 更像“数学上最平滑的电源”，而不是一台真实柴油发电机。

### 3.2 Proxy

`Proxy` 是当前项目默认模式。

它的基本逻辑是：

1. 先用 `LP` 求全年逐小时出力
2. 再根据柴油出力序列反推“哪些小时应该算开机”
3. 再用最小负载率、启停状态代理、最低稳定运行功率，对油耗和运行小时做修正

可以把它理解成：

- 先算出力
- 再补上真实机组约束的主要影响

优点：

- 速度快
- 比纯 `LP` 更接近真实机组
- 更适合作为默认在线交互模式

缺点：

- 启停状态不是在优化阶段原生决定的，而是后处理近似得到的
- 仍然不是完整 `UC`

一句话：

`Proxy` 是“速度和真实性的折中方案”。

### 3.3 UC

`UC` 是 `Unit Commitment`，中文通常叫“机组组合”或“机组启停优化”。

它与 `LP` 的本质区别是：

- 不只是算柴油机这一小时发多少电
- 还要同时决定这一小时机组“开还是关”

典型会考虑：

- 最小负载率
- 启停状态
- 最小开机时间
- 最小停机时间
- 启动成本
- 停机成本

可以把它理解成：

- `LP`：只优化“出多少”
- `UC`：优化“开不开 + 出多少”

优点：

- 最接近真实柴油机运行逻辑
- 最适合解释启停次数、低负载油耗和机组行为

缺点：

- 在 `PyPSA + 全年 8760 小时 + 储能 + 二进制变量` 的链路里最慢
- 不适合作为默认在线交互模式

一句话：

`UC` 更接近真实工程机组，但计算代价最大。

## 4. HOMER Pro 更像哪一种

HOMER Pro 不是当前 `LP / Proxy / UC` 三种中的任何一个“原样版本”。

更准确地说：

- 从物理行为上看，HOMER Pro 更接近 `UC`
- 从求解方式上看，HOMER Pro 并不像当前项目这样用通用优化器去硬解全年 `8760h` UC
- 从工程实现上看，HOMER Pro 更像“带真实机组规则的专用逐时调度仿真器”

HOMER 常见的调度风格更接近：

- `Load Following`
- `Cycle Charging`

同时还会显式考虑：

- 柴油机最小负载
- 电池是否优先放电
- 柴油机是否顺带给电池充电
- reserve SOC
- 燃油曲线
- 经济性排序

因此可以概括为：

- `LP`：HOMER 不是这个
- `Proxy`：HOMER 也不是这个
- `UC`：在“有真实启停和最小负载约束”这一层意义上，HOMER 更接近这个
- 但 HOMER 并不等于当前这套“全年通用 UC”实现

## 5. 为什么同一套输入，三种模式结果会不同

因为真实柴油机并不是“想发多少就能稳定发多少”的理想电源。

真实机组通常有两个关键事实：

- 一旦开机，就存在基础油耗
- 低负载运行时效率会明显变差

因此这三种模式的差异并不是单纯数学形式不同，而是对“柴油机是不是一台真实机组”的假设不同。

一般规律是：

- `LP` 往往低估真实油耗
- `LP` 容易把柴油机切成很多小功率碎片运行
- `Proxy` 会把这类低负载小时修正得更真实
- `UC` 会直接改变最优调度路径，因为它从一开始就不允许不真实的开机状态

## 6. 直观例子一：单小时低负载

假设：

- 柴油机额定功率：`40 kW`
- 最小负载率：`30%`
- 因此最小稳定出力：`12 kW`
- 某一小时负荷：`8 kW`

### 6.1 LP 会怎么处理

`LP` 可能直接让柴油机发：

- `8 kW`

因为对它来说，只要供需平衡即可。

问题是：

- 数学上成立
- 工程上不真实

因为真实机组通常不能长期稳定运行在 `20%` 这样低于最小负载率的状态。

### 6.2 Proxy 会怎么处理

`Proxy` 先接受 `LP` 给出的 `8 kW` 出力结果，但在油耗计算阶段会认为：

- 这一小时已经算“机组开机”
- 既然开机，就不应按 `8 kW` 的理想化状态算油耗
- 而应至少按最小负载 `12 kW` 对应的运行状态修正油耗

因此：

- 供电结果仍然可能保留 `8 kW`
- 但油耗会按更真实的开机状态修正

### 6.3 UC 会怎么处理

`UC` 在优化阶段就知道：

- 机组开机后不能低于 `12 kW`

所以它不会允许“开机却只发 `8 kW`”这种状态进入最优解。

它只能在这些策略中选择：

- 不开机，让电池供电
- 开机并至少发 `12 kW`
- 多出的电去充电或弃掉
- 在更长时间尺度上调整启停时点，减少总成本

## 7. 直观例子二：连续 6 小时负荷变化

仍然假设：

- 柴油机额定功率：`40 kW`
- 最小负载率：`30%`
- 最小稳定出力：`12 kW`

负荷序列如下：

- 第1小时：`5 kW`
- 第2小时：`8 kW`
- 第3小时：`15 kW`
- 第4小时：`6 kW`
- 第5小时：`18 kW`
- 第6小时：`4 kW`

并假设：

- 电池容量有限，但不是无限大
- 柴油机每次启动都有代价
- 频繁低负载运行不划算

### 7.1 LP 的典型思路

`LP` 只关心每小时平衡，不关心真实启停。

它可能会给出一条几乎“紧贴负荷”的柴油出力：

- 第1小时：`5`
- 第2小时：`8`
- 第3小时：`15`
- 第4小时：`6`
- 第5小时：`18`
- 第6小时：`4`

这条曲线在数学上很好看，但工程上不真实：

- 柴油机像一个无限可调电源
- 完全没有最小稳定出力约束

### 7.2 Proxy 的典型思路

`Proxy` 仍然从 `LP` 出力开始，但后处理会做两件事：

- 识别哪些小时应该算作“机组开机”
- 在这些开机小时里，用最小负载约束修正油耗

其结果通常表现为：

- 油耗比 `LP` 更高
- 运行小时更合理
- 可以统计出更合理的启动次数

### 7.3 UC 的典型思路

`UC` 的优化目标不是“每小时尽量刚好跟着负荷”，而是“考虑真实机组代价后的全年总最优”。

因此它可能做出这种策略：

- 第1小时：先不开机，电池顶负荷
- 第2小时：继续不开机，避免提前启动
- 第3小时：开机，满足较高负荷
- 第4小时：即使负荷只有 `6 kW`，也可能继续开机，以避免停机后又启动
- 第5小时：继续开机，满足 `18 kW`
- 第6小时：如果后续负荷低，则停机，由电池承担

这就是为什么 `UC` 在行为上最接近真实机组。

## 8. 为什么 HOMER Pro 看起来快，而当前 UC 很慢

这并不意味着两者在求解完全相同的问题。

当前项目的 `UC` 慢，主要因为：

- 采用的是 `PyPSA + 通用优化器`
- 做的是全年 `8760` 小时带二进制启停变量的优化
- 还叠加了储能 SOC、充放电、弃光、缺供等耦合变量

这类问题一旦上全年 `UC`，求解规模会显著膨胀。

HOMER Pro 更可能采用的是：

- 专用微电网 dispatch 仿真逻辑
- 针对 PV/储能/柴油机的专门求解流程
- 更强的方案筛选与剪枝
- 专用工程优化实现

因此：

- 看起来都在做“全年 + 启停 + 经济对比”
- 但底层求解路线很可能并不一样

## 9. 为什么柴油机运行时间会偏差这么大

在相同项目输入下，如果 HOMER Pro 得到 `889 h`，而当前项目分别得到：

- `Continuous LP = 1498 h`
- `Proxy Min-Load = 1279 h`

那么偏差来源通常不是单个参数，而是整套调度逻辑不同。

最核心的问题是：

- 柴油机什么时候应该算“开机”
- 什么时候应该由电池承担
- 什么时候柴油机应该连续撑住而不是零碎出力

这些规则在 HOMER Pro 中通常是通过专用 dispatch 策略实现的，而当前项目还没有完整复刻。

### 9.1 为什么 LP 会明显偏高

`Continuous LP` 的本质是：

- 柴油机只决定“每小时发多少电”
- 不决定“这一小时机组是否真实开机”
- 也不会在优化阶段显式考虑最小负载、启动代价、停机代价

因此它很容易出现：

- 很多小时只有很小功率，但仍然算在柴油出力中
- 这些小时在统计时会被记成运行小时
- 机组像一个理想连续电源，而不是真实柴油发电机

结果就是：

- 柴油运行小时被放大
- 柴油机低负载碎片运行过多
- 与 HOMER Pro 的真实机组逻辑差距最大

所以 `1498 h` 比 `889 h` 高很多是符合预期的。

### 9.2 为什么 Proxy 虽然更接近，但还是偏高

`Proxy Min-Load` 的改进点在于：

- 它会从 `LP` 的柴油出力结果中反推开机状态
- 再结合最小负载率和最小负载燃油修正
- 让低负载小时的油耗和运行状态更接近真实机组

所以 `Proxy` 相比 `LP` 会更接近 HOMER Pro。

从这组结果也能看出来：

- `1498 h -> 1279 h`

说明方向是对的。

但它仍然没有降到 `889 h`，原因是：

- `Proxy` 只是“后处理代理”
- 它不是在优化阶段原生决定启停
- 它不能像 HOMER Pro 一样，在每个时段里真正做出“不开机、继续用电池”或者“开机顺便给电池充电”的动态决策

### 9.3 为什么 HOMER Pro 会比当前项目更少运行小时

这通常由以下几类原因共同造成：

- HOMER 的 dispatch 策略不同
- 电池控制逻辑不同
- 输入时序不完全一致
- 柴油机细节参数未完全校准
- 当前运行小时定义与 HOMER 不完全等价

## 10. 当前结果应该怎么解读

如果某个项目下出现：

- HOMER Pro：`889 h`
- `LP`：`1498 h`
- `Proxy`：`1279 h`

那么正确解读应为：

- `LP` 过度理想化，偏差最大
- `Proxy` 的确在把模型往 HOMER Pro 拉近
- 但当前系统仍然比 HOMER 更容易让柴油机参与更多小时

所以这组数据不是在证明“改错了”，而是在说明：

- 方向对了
- 但距离完整复现 HOMER Pro 的 dispatch 行为还有最后一段路

## 11. 可直接用于汇报的一句话模板

当前系统已经从“连续理想化柴油机”推进到“考虑最小负载和启停代理”的近似模型，因此柴油机运行小时已从 `1498 h` 向 HOMER Pro 的 `889 h` 收敛；但由于当前仍未完整复现 HOMER Pro 的专用 dispatch 规则和电池协同策略，所以柴油机运行小时仍偏高。

## 12. 如果目标是进一步逼近 HOMER Pro，优先级应该是什么

如果目标是继续让结果页尽量逼近 HOMER Pro，建议优先顺序如下：

1. 导入与 HOMER 完全一致的 `8760` 负荷、太阳资源、温度数据
2. 按 HOMER 项目逐项校准柴油机和电池参数
3. 补一版更接近 HOMER 的专用 dispatch 规则，而不是继续依赖通用 `PyPSA` 代理口径

### 12.1 数据统一

必须尽量统一：

- 负荷序列
- 太阳资源序列
- 温度序列

如果输入时序不同，运行小时很难完全对齐。

### 12.2 设备参数校准

建议校准的关键参数包括：

- 最小负载率
- 燃油曲线系数
- 启动成本
- 停机成本
- 维护参数
- 寿命小时数
- 最小开停机时间

### 12.3 补专用 dispatch 规则

这是当前最关键的下一步。

建议实现：

- `Load Following / Cycle Charging` 策略切换
- `reserve SOC`
- `generator charging`
- 真实机组开机状态驱动的运行小时统计

这一步比继续微调 `Proxy` 阈值更重要，因为偏差本质在“调度规则”而不只在“统计口径”。

## 13. 一句话总括

三种模式的本质区别在于：

- `LP` 把柴油机当理想电源
- `Proxy` 承认它是现实机组，但用后处理近似修正
- `UC` 从优化阶段起就把它当成真实机组

而 HOMER Pro 更像“带真实机组规则的专用逐时调度仿真器”。

因此如果目标是“速度 + 接近 HOMER Pro”，当前默认采用 `Proxy` 是合理的；如果目标是“最真实的启停逻辑”，则应使用 `UC` 做验证；如果目标是“结果页几乎贴住 HOMER Pro”，则下一步必须推进统一输入数据、设备参数校准以及更接近 HOMER 的专用 dispatch 规则。

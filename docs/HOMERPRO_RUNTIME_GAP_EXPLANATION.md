# HOMER Pro 运行时间偏差解释与后续对齐方向

## 1. 结论

当前项目已经明显朝 HOMER Pro 靠近，但还没有做到“同输入条件下与 HOMER Pro 完全一致”。

这次最典型的差异是柴油机年运行时间：

- HOMER Pro：`889 h`
- `Continuous LP`：`1498 h`
- `Proxy Min-Load`：`1279 h`

这组结果说明：

- `LP` 明显偏理想化
- `Proxy` 已经在向 HOMER Pro 收敛
- 但当前实现仍比 HOMER Pro 更倾向于让柴油机在更多小时里介入

所以准确说法不是“模型错了”，而是：

- 现在已经不是旧模型
- 已经比原来更接近 HOMER Pro
- 但还没有完整复现 HOMER Pro 的调度实现方式

## 2. 当前是不是和 HOMER Pro 一模一样

不是一模一样，当前是“尽量对齐 HOMER Pro 口径”，但还没有做到“同输入必然逐项完全一致”。

### 2.1 已经明显对齐的部分

当前已经对齐得比较多的部分包括：

- 成本/经济主口径已经切到 `NPC -> annualized cost -> COE`
- 柴油燃油已经改成 HOMER 风格线性燃油曲线
- 纯柴油基准场景已经改成独立仿真，不再是经验换算
- 柴油机寿命、电池寿命、残值、贴现现金流这些已经按 HOMER 思路重构了
- 后端已经支持三种柴油调度模式，默认是 `proxy`

### 2.2 仍然没有完全一致的关键点

当前与 HOMER Pro 仍不完全一样的关键点包括：

- 电池控制逻辑不一样
  HOMER 常见的 `Load Following / Cycle Charging / reserve SOC / generator charging` 规则，我们这边还没完整复刻。
- 输入数据源可能不一样
  如果没有导入和 HOMER 完全相同的 `8760` 负荷、气象、温度序列，结果不会完全一致。
- 柴油机细节参数还没完全按 HOMER 设备卡校准
  比如最小负载、燃油曲线系数、启动成本、寿命小时数、维护参数，差一点都会把年油耗和年运行时间拉开。

所以更准确的说法是：

- 当前实现已经明显更接近 HOMER Pro
- 但还不是“与 HOMER Pro 一模一样”

## 3. 为什么柴油机运行时间会偏差这么大

在相同项目输入下，如果 HOMER Pro 得到 `889 h`，而当前项目分别得到：

- `Continuous LP = 1498 h`
- `Proxy Min-Load = 1279 h`

那么偏差来源通常不是单个参数，而是整套调度逻辑不同。

最核心的问题是：

- 柴油机什么时候应该算“开机”
- 什么时候应该由电池承担
- 什么时候柴油机应该连续撑住而不是零碎出力

这些规则在 HOMER Pro 中通常是通过专用 dispatch 策略实现的，而当前项目还没有完整复刻。

## 4. 为什么 LP 会明显偏高

`Continuous LP` 的本质是：

- 柴油机只决定“每小时发多少电”
- 不决定“这一小时机组是否真实开机”
- 也不会在优化阶段显式考虑最小负载、启动代价、停机代价

因此它很容易出现：

- 很多小时只有很小功率，但仍然算在柴油出力中
- 这些小时在统计时会被记成运行小时
- 机组像一个理想连续电源，而不是真实柴油发电机

结果就是：

- 柴油运行小时被放大
- 柴油机低负载碎片运行过多
- 与 HOMER Pro 的真实机组逻辑差距最大

所以 `1498 h` 比 `889 h` 高很多是符合预期的。

## 5. 为什么 Proxy 虽然更接近，但还是偏高

`Proxy Min-Load` 的改进点在于：

- 它会从 `LP` 的柴油出力结果中反推开机状态
- 再结合最小负载率和最小负载燃油修正
- 让低负载小时的油耗和运行状态更接近真实机组

所以 `Proxy` 相比 `LP` 会更接近 HOMER Pro。

从你这组结果也能看出来：

- `1498 h -> 1279 h`

说明方向是对的。

但它仍然没有降到 `889 h`，原因是：

- `Proxy` 只是“后处理代理”
- 它不是在优化阶段原生决定启停
- 它不能像 HOMER Pro 一样，在每个时段里真正做出“不开机、继续用电池”或者“开机顺便给电池充电”的动态决策

也就是说：

- `Proxy` 能修正结果
- 但还不能替代 HOMER 的专用 dispatch 逻辑

## 6. 为什么 HOMER Pro 会比当前项目更少运行小时

这通常由以下几类原因共同造成。

### 6.1 HOMER 的 dispatch 策略不同

HOMER Pro 常见的核心调度策略包括：

- `Load Following`
- `Cycle Charging`

这两类策略会直接影响：

- 柴油机什么时候开
- 开机时是否只带当前负荷
- 开机时是否顺便给电池充电
- 电池应优先放电还是优先留作备用

当前项目虽然已经接近 HOMER 的结果风格，但仍没有完整复刻这套专用策略。

### 6.2 电池控制逻辑不同

当前与 HOMER Pro 最大的未对齐点之一就是电池调度。

HOMER 常见会显式处理：

- `reserve SOC`
- `generator charging`
- `Load Following`
- `Cycle Charging`

只要电池策略不同，就会直接改变：

- 柴油机何时启动
- 柴油机每次连续运行多久
- 柴油机全年总运行小时

这通常是运行时间差异的重要来源。

### 6.3 输入时序不完全一致

即使名义上都叫 `8760`，只要下列任意一项不完全一致，柴油机运行时间就会明显变化：

- 负荷时序
- 太阳资源时序
- 温度序列
- 气象站或数据源

柴油机运行小时对这些时序非常敏感，因此如果没有和 HOMER Pro 使用完全一致的输入序列，结果不会完全一致。

### 6.4 柴油机细节参数未完全校准

当前还可能没有完全按 HOMER 项目中同一台设备的真实参数校准，例如：

- 最小负载率
- 燃油曲线系数
- 启动成本
- 寿命小时数
- 维护参数
- 最小开机时间
- 最小停机时间

这些参数看起来只是细节，但会显著改变：

- 开机次数
- 运行小时
- 年油耗
- NPC
- COE

### 6.5 当前运行小时定义与 HOMER 不完全等价

在理想化或近似模型里，运行小时常常通过功率阈值近似定义，例如：

- `P > 某阈值` 就算该小时运行

但 HOMER Pro 的机组运行时间更接近真实开机状态，而不是单纯的功率阈值统计。

因此：

- 在 `LP` 下，很多碎片化小出力小时都会被算成运行
- 在 `Proxy` 下虽然做了修正，但仍未必完全等价于 HOMER 的机组状态统计方式

## 7. 这组结果应该怎么解读

你当前的结果：

- HOMER Pro：`889 h`
- `Continuous LP`：`1498 h`
- `Proxy Min-Load`：`1279 h`

它传递出的信息是：

- `LP` 过度理想化，偏差最大
- `Proxy` 的确在把模型往 HOMER Pro 拉近
- 但当前系统仍然比 HOMER 更容易让柴油机参与更多小时

所以这组数据不是在证明“改错了”，而是在说明：

- 方向对了
- 但距离完整复现 HOMER Pro 的 dispatch 行为还有最后一段路

## 8. 一句话解释模板

可直接用于内部或客户沟通：

当前系统已经从“连续理想化柴油机”推进到“考虑最小负载和启停代理”的近似模型，因此柴油机运行小时已从 `1498 h` 向 HOMER Pro 的 `889 h` 收敛；但由于当前仍未完整复现 HOMER Pro 的专用 dispatch 规则和电池协同策略，所以柴油机运行小时仍偏高。

## 9. 如果目标是进一步把 1279 h 拉近 889 h，应该优先做什么

如果目标是继续逼近 HOMER Pro，建议优先级如下。

### 9.1 导入与 HOMER 完全一致的 8760 数据

必须尽量统一：

- 负荷序列
- 太阳资源序列
- 温度序列

如果输入时序不同，运行小时很难完全对齐。

### 9.2 按 HOMER 项目逐项校准柴油机参数

需要校准的关键参数包括：

- 最小负载率
- 燃油曲线系数
- 启动成本
- 停机成本
- 维护参数
- 寿命小时数
- 最小开停机时间

### 9.3 补一版更像 HOMER 的专用 dispatch 规则

这是当前最关键的下一步。

建议实现：

- `Load Following / Cycle Charging` 策略切换
- `reserve SOC`
- `generator charging`
- 真实机组开机状态驱动的运行小时统计

这一步比继续微调 `Proxy` 阈值更重要，因为偏差本质在“调度规则”而不只在“统计口径”。

## 10. 总结

当前项目已经不是旧模型，也已经明显更接近 HOMER Pro，但仍没有做到完全一致。

尤其在柴油机年运行时间上：

- `LP` 偏差大，说明理想化连续机组假设不够真实
- `Proxy` 已经往 HOMER Pro 收敛，但仍然偏高
- 差异的核心来自：
  - 调度策略
  - 电池控制逻辑
  - 输入时序
  - 柴油机细节参数

因此，如果目标是让当前结果页尽量逼近 HOMER Pro，下一阶段最值得优先推进的是：

1. 统一 `8760` 输入数据
2. 校准柴油机与电池参数
3. 实现更接近 HOMER Pro 的专用 dispatch 规则
